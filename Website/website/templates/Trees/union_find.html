Union-Find (Disjoint Set Union)

Union-Find maintains a collection of disjoint sets under two operations: find(x) — which set does x belong to? — and union(x, y) — merge the set containing x with the set containing y. Each set is represented as a tree whose root is the set's representative; every node points at its parent, and following parents upward from any element reaches the representative. Kruskal's minimum spanning tree algorithm, connected components, and cycle detection all reduce to these two operations.

Union Operation — Visualized

The animation starts with nine singleton sets — 26, 7, 2, 25, 19, 17, 1, 90, 3, each element its own representative — and merges them step by step. Watch the two Find steps inside every union: they locate the two roots before anything is linked.

What the animation shows: one set is circled and labelled Set — a representative with its members. Then the unions run in sequence:

  • Union(26, 7): Find(26) => 26, Find(7) => 7 — 26's set is attached under 7's representative (the members slide over and a link is drawn), leaving one set labelled Union Set with 7 as its Set Representative.
  • The following unions repeat the pattern: Union(2, 25), Union(2, 19) (2's set already has root 25, so 25's set attaches under 19), Union(2, 26) (2's root is 19, 26's root is 7 — merged under 7), Union(1, 17), Union(90, 1), Union(90, 3), and finally Union(2, 1), which links the two big trees: Find(2) => 7 and Find(1) => 3, so 7's set is attached under 3.
  • All nine elements end in one set with representative 3 — the final frame's single group.

The animation uses the plain form of the structure — find walks parents without changing them, and union always attaches the first set's root under the second's. The code shown (and the reference implementation) adds the two standard optimisations below, which keep the trees from degenerating into long chains.

The Two Optimisations

  • Path compression (find): as the parents are walked, every node visited is re-pointed directly at the root. The next find from any of those nodes is one hop. In the animation's terms: after Find(2) walks 2 → 25 → 19 → 7, compression would leave 2, 25 and 19 all pointing straight at 7.
  • Union by rank (union): attach the shallower tree under the deeper one (rank approximates height; equal ranks merge and the root's rank grows by one). The animation's plain attachment can build chains — the rank rule is what prevents that systematic worst case.

Together they make every operation run in $O(\alpha(n))$ amortized time, where $\alpha$ is the inverse Ackermann function — for all practical input sizes $\alpha(n) \le 4$, so each find/union behaves as a near-constant-time operation. Space is $\Theta(n)$: one parent slot (and one rank slot) per element.

Without the optimisations — as animated — find is $O(n)$ worst case (a chain of $n$ parents, e.g. the sequence Union(0,1), Union(1,2), Union(2,3) … builds one), giving $O(n^2)$ for $n$ unions. Best case remains $O(1)$ per find (every element points straight at its representative). The rank rule alone or the compression alone already gives $O(\log n)$-ish behaviour; the pair together gives the $\alpha(n)$ bound.

Must know: a union whose two find calls return the same root is a no-op — the elements are already in one set (the code returns False). Counting those no-ops is how algorithms like Kruskal's know when to stop adding edges: n - 1 successful unions mean every pair is connected.

Applications

  • Kruskal's MST algorithm: sort the edges, accept an edge only if its endpoints lie in different sets (union succeeds) — the union-find checks make the whole algorithm $O(E \log E)$.
  • Connected components: union every edge's endpoints; the remaining roots are the components.
  • Cycle detection in an undirected graph: an edge whose endpoints already share a set closes a cycle.
  • Dynamic equivalence problems — percolation, network connectivity, "are these accounts the same person" — anywhere the question is are these two things in the same group yet?
