Binary Search Tree

A binary search tree (BST) is a binary tree with one ordering rule: for every node, everything in its left subtree is smaller and everything in its right subtree is greater or equal. That single rule turns the tree into a sorted structure — searching walks one path from the root, and an in-order traversal lists all values in sorted order.

Insertion

Inserting a value repeats one step: compare with the current node and go left or right — smaller values left, larger (or equal) values right — until an empty slot is found. The new node takes that slot. No other node changes: an insertion touches exactly one path from the root.

Worked example — the animation's insertions one by one:

  • 26 arrives first — it becomes the root.
  • 7: 7 < 26 → left child of 26.
  • 2: 2 < 26 → left to 7; 2 < 7 → left child of 7.
  • 25: 25 < 26 → left to 7; 25 ≥ 7 → right child of 7.
  • 19: 19 < 26 → left to 7; 19 ≥ 7 → right to 25; 19 < 25 → left child of 25.
  • 47: 47 ≥ 26 → right child of 26.
  • 1: 1 < 26 → left to 7; 1 < 7 → left to 2; 1 < 2 → left child of 2.
  • 90: 90 ≥ 26 → right to 47; 90 ≥ 47 → right child of 47.
  • 36: 36 ≥ 26 → right to 47; 36 < 47 → left child of 47.
  • 3: 3 < 26 → left to 7; 3 < 7 → left to 2; 3 ≥ 2 → right child of 2.

The final tree places 26 at the root over 7 and 47, with 7 over 2 and 25, 2 over 1 and 3, 25 over 19, and 47 over 36 and 90. Walking it in-order reads 1 2 3 7 19 25 26 36 47 90 — sorted, as the BST property promises.

Complexity: each comparison descends one level, so insertion costs $O(h)$ where $h$ is the tree height: best case $O(\log n)$ on a balanced tree (the comparisons halve the remaining candidates at each step — the same recurrence $T(n) = T(n/2) + O(1)$ as binary search), worst case $O(n)$ when the tree has degenerated into a chain (sorted insertion order — each arrival walks the entire existing spine), and average $O(\log n)$ over random insertion orders. Space is $O(h)$ for the recursion stack.

Deletion — Four Cases

Deletion first searches for the node (the same left/right walk as insertion), then handles what kind of node it found. The animation builds the same tree plus one extra value 34 (34 → right of 26, left of 47, left of 36), then deletes three nodes covering three of the cases:

The four cases (the scene implements all four; the video animates 1, 2 and 4):

  • Case 1 — leaf (animated: deleting 1): the node has no children; simply remove it and its edge to the parent.
  • Case 2 — one child, a left subtree (animated: deleting 25, whose only child is 19): the child moves up into the deleted node's position — 25's slot now holds 19.
  • Case 3 — one child, a right subtree: symmetric — the right child moves up. Present in the code, not shown in this particular animation.
  • Case 4 — two children (animated: deleting the root 26): the node is replaced by its in-order successor — the smallest value in its right subtree. The animation shows the exact procedure: go right (to 47), then keep going left (to 36, then to 34 — the leftmost node). 34's value replaces 26 at the root, and 34 is then removed from its original slot — where it had at most a right child, so that removal is itself a simple case. This is exactly the notebook's leftmost(node.right) rule: the successor is guaranteed to have no left child, so deleting it never recurses into case 4 again.

Why the in-order successor? Every value between the deleted node's left subtree and its right subtree qualifies as its replacement; the successor is the smallest such value — the leftmost node of the right subtree — so both subtrees remain valid after the swap.

Complexity: the search phase costs $O(h)$; each case then rewires at most a constant number of pointers (case 4 additionally walks to the successor, still bounded by the height), so deletion is $O(h)$ overall — $O(\log n)$ balanced, $O(n)$ degenerate. Space $O(h)$ recursion depth.

Properties, Pitfalls and Comparisons

  • In-order = sorted: the BST rule makes an in-order traversal list values in ascending order — the fastest way to sanity-check a BST.
  • Search = one-path insert: searching reuses the insert walk with an equality check; same $O(h)$ bound.
  • Pitfall — sorted insertions: inserting already-sorted data builds a chain (every value goes right), degrading every operation to $O(n)$ — the BST becomes a linked list. This is the motivation for self-balancing trees such as AVL trees, which rotate to keep $h = O(\log n)$.
  • vs. heaps: a heap only orders parents against children — finding an arbitrary value still needs a full scan; a BST orders all values against each other, enabling $O(h)$ search. Heaps win on find-min/max and array storage.
