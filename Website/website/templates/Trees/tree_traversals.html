Tree Traversals

A traversal is a systematic way to visit every node of a tree exactly once. Two families cover everything: breadth-first walking level by level through a queue, and depth-first diving to a leaf before backtracking — with three recursive orders that differ only in when the current node is processed relative to its two subtrees.

The animations below use two demo trees: the BFS and DFS videos walk the general 11-node tree A–(B, C), B–(D, E), C–(F, G, H), D–(I, J), E–(K), while the three recursive orders run on the binary tree A–(B, C), B–(D, E), D–(H, I), C–(F, G), E–(J).

Breadth-First Search (Level-Order) — the Queue

BFS visits the root first, then the root's children, then the grandchildren — level by level. A FIFO queue makes this natural: join newly discovered nodes at the rear, always take the next node to process from the front. The oldest waiting node always belongs to the shallowest unfinished level, so levels complete in order.

What the animation shows: starting from node A, the queue display at the top tracks the container — Queue: [A], then after A is processed, Queue: [B, C], and so on. Each processed node is highlighted, its unvisited neighbours are selected and join the rear of the queue, and the front node leaves in turn. The visit order for this tree is A B C D E F G H I J K — exactly the level order.

Complexity: every node enters and leaves the queue once, so time is $\Theta(n)$ (best = worst = average — every traversal must touch all $n$ nodes). Space is $O(w)$ where $w$ is the maximum number of nodes queued at once — at most an entire level, which for a balanced binary tree is $\Theta(n/2)$ at the widest level, and for a path-shaped tree is $O(1)$.

Depth-First Search — the Stack

DFS dives along one path as deep as possible before backing up. A LIFO stack provides the memory for the backtrack: newly discovered children join the top, and the next node processed is always the most recently discovered one — so the dive continues instead of spreading out.

What the animation shows: the same tree and the same highlight pattern as BFS — but the container at the top now reads Stack, and nodes leave from the top (the newest entry), not the front. The stack runs [A] → [C, B] → [C, E, D] → [C, E, I, H] → … as the traversal dives down the B branch to its leaves before ever touching C. The visit order is A B D I J E K C F G H — one full root-to-leaf dive at a time.

Complexity: time $\Theta(n)$, same argument as BFS. Space is $O(h)$ — the stack holds one pending sibling set per level of the current dive, bounded by the tree height $h$: $O(n)$ for a degenerate chain, $O(\log n)$ for a balanced tree. This $O(h)$ bound is the classic argument for preferring DFS over BFS when the tree is deep and narrow.

In-Order Traversal — Left, Root, Right

The three recursive orders differ only in when the current node is visited: in-order processes the left subtree first, then the node itself, then the right subtree. On a binary search tree this visits values in sorted order.

What the animation shows: the recursion literally walks the tree — the blue edge marks each "going to left subtree" step, the green edge each "going to right subtree" step, and the Order display at the top grows as nodes are processed. The run bottoms out at the leftmost leaf H before anything is appended. The final order for the demo tree is H D I B J E A F C G.

Complexity: time $\Theta(n)$ — the recursion visits every node exactly once (the recurrence $T(n) = T(n_L) + T(n_R) + O(1)$ sums to $n$ calls). Space is the recursion stack: $O(h)$ — $O(n)$ worst case on a degenerate tree, $O(\log n)$ balanced.

Pre-Order Traversal — Root, Left, Right

Pre-order processes the node first, then recurses into the left and right subtrees. It is the order for copying serialising a tree (a node is known before its children, so the reader can build it), and it is exactly the order the DFS stack produced above.

What the animation shows: node A is processed immediately — position 1 in the order display — before the walk descends into B's subtree. The order grows one node at a time as the recursion descends, completing the whole left side before C. The final order is A B D H I E J C F G.

Complexity: time $\Theta(n)$, space $O(h)$ recursion stack — identical analysis to in-order; only the position of the visit call changed.

Post-Order Traversal — Left, Right, Root

Post-order processes both subtrees first, then the node itself. Children complete before their parent — exactly what deleting or freeing a tree needs (and what evaluating an expression tree needs: operands before the operator that combines them).

What the animation shows: nothing enters the order display until the first leaf H completes — the root A is processed last, position 10. Both children always precede their parent in the growing order line. The final order is H I D J E B F G C A.

Complexity: time $\Theta(n)$, space $O(h)$ — the same recurrence as its siblings.

Comparing the three: the same ten nodes, three different valid orders — in-order H D I B J E A F C G, pre-order A B D H I E J C F G, post-order H I D J E B F G C A. Each is the same recursion with the visit line moved; each is $\Theta(n)$ time and $O(h)$ stack space. Pre-order serialises, in-order sorts (on a BST), post-order frees/evaluates — pick by purpose, not by performance.
