Graph Representation

Whatever kind of graph you have — undirected, directed, weighted — a program must store it in memory. The two classic structures are the adjacency matrix (a $V \times V$ grid) and the adjacency list (one neighbour list per vertex). The eight animations below build all $2 \times 2 \times 2$ combinations — matrix/list × undirected/directed × unweighted/weighted — on a shared 5-vertex demo graph, so the trade-offs are directly comparable.

Matrix vs. List at a Glance

Operation Adjacency matrix Adjacency list
Space $\Theta(V^2)$ — always $\Theta(V + E)$
Has edge (u, v)? $O(1)$ — one array read $O(\deg(u))$ — scan the list
List all neighbours of u $\Theta(V)$ — whole row $\Theta(\deg(u))$ — read the list
Add/remove edge $O(1)$ $O(1)$ add / $O(\deg(u))$ remove

The rule of thumb: a matrix wins on dense graphs (many of the $V^2$ cells used) and on constant-time edge queries; a list wins on sparse graphs — which most real graphs are — because $V + E$ is far below $V^2$.

Band 1 — Unweighted

The four unweighted videos share one demo graph on vertices 0–4 with edges (0,1), (0,2), (1,3), (1,4), (2,3), (2,4), (4,3) — the exact edge list from the reference implementation. Watch each structure fill in edge by edge.

Adjacency Matrix — Undirected

A $V \times V$ grid of zeros; edge (u, v) sets both M[u][v] and M[v][u] — the matrix of an undirected graph is always symmetric about its diagonal.

What the animation shows: the graph appears, then an empty 5×5 matrix. Each edge lights up on the graph while two mirrored cells flip to 1 — e.g. edge (1, 3) writes both M[1][3] and M[3][1]. Row 1 ends up 1 0 0 1 1: vertex 1's neighbours at a glance. Seven edges → fourteen cells set.

Adjacency List — Undirected

One list per vertex. Edge (u, v) appends v to u's list and u to v's list; the list length of a vertex is exactly its degree.

What the animation shows: the same graph beside five empty rows 0:  1:  2: .... Each edge highlights both endpoints' rows and grows both lists — edge (1, 3) pushes 3 into row 1 and 1 into row 3. Final lists: 0: [1, 2] · 1: [0, 3, 4] · 2: [0, 3, 4] · 3: [1, 2, 4] · 4: [1, 2, 3] — 14 total entries, two per edge.

Adjacency Matrix — Directed

Direction changes one thing: edge (u, v) sets only M[u][v]. The matrix is generally no longer symmetric — a 1 at M[u][v] with 0 at M[v][u] is exactly a one-way street.

What the animation shows: the same seven edges, but each writes a single cell — 7 cells instead of 14. Row u is u's out-neighbours, column v is v's in-neighbours; M[3][4] = 1 while M[4][3] = 0 encodes the one-way edge 4–3... drawn as 4→3? Check the video: the edge written is (4, 3), so M[4][3] = 1 and M[3][4] stays 0 — the asymmetry is the direction.

Adjacency List — Directed

Only the tail's list grows: edge (u, v) appends v to u's list and nothing else. Each row is that vertex's out-neighbours; its length is its out-degree.

What the animation shows: each edge highlights only its tail's row — edge (1, 3) grows row 1 only. Final lists: 0: [1, 2] · 1: [3, 4] · 2: [3, 4] · 3: [4] · 4: [3] — exactly 7 entries, one per edge, against the undirected version's 14.

Band 2 — Weighted

The four weighted videos share the demo weights (0,1,10), (0,3,18), (1,2,20), (1,3,6), (2,4,8), (3,4,70) on vertices 0–4 — the same weights the shortest-path and MST pages use. A cell (or list entry) now stores the weight instead of a 1; "no edge" is a 0 in the matrix and an absent entry in the list.

Weighted Adjacency Matrix — Undirected

Edge (u, v, w) writes w into both M[u][v] and M[v][u]. The matrix is symmetric again, and reading M[u][v] answers "what does the edge cost?" in one step.

What the animation shows: each weighted edge writes its weight into two mirrored cells — edge (1, 3, 6) writes 6 into both M[1][3] and M[3][1]. Final matrix rows: 0: [0, 10, 0, 18, 0] · 1: [10, 0, 20, 6, 0] · 2: [0, 20, 0, 0, 8] · 3: [18, 6, 0, 0, 70] · 4: [0, 0, 8, 70, 0].

Weighted Adjacency List — Undirected

List entries become (neighbour, weight) ordered pairs — exactly the tuples the video displays. Edge (u, v, w) appends (v, w) to u's list and (u, w) to v's list.

What the animation shows: each edge highlights both rows and appends a (neighbour, weight) pair to each — e.g. edge (0, 3, 18) writes (3, 18) into row 0 and (0, 18) into row 3, displayed as the tuples you see growing on the right. Final rows: 0: [(1,10), (3,18)] · 1: [(0,10), (2,20), (3,6)] · 2: [(1,20), (4,8)] · 3: [(0,18), (1,6), (4,70)] · 4: [(2,8), (3,70)].

Weighted Adjacency Matrix — Directed

One direction, one weight: edge (u, v, w) writes only M[u][v] = w. Asymmetry now means "the reverse edge doesn't exist or costs something else".

What the animation shows: the weights write single cells — note the demo's directed edge is (4, 3, 70), so 70 lands in M[4][3] only and M[3][4] stays 0. Row 4 reads 0 0 0 70 0: one out-edge, cost 70.

Weighted Adjacency List — Directed

The tail's list gains an (out-neighbour, weight) ordered pair — one append per edge, exactly as the tuples appear in the video.

What the animation shows: one row grows per edge — (1, 3, 6) appends (3, 6) to row 1 only, and the directed edge (4, 3, 70) appends (3, 70) to row 4. Final rows: 0: [(1,10), (3,18)] · 1: [(2,20), (3,6)] · 2: [(4,8)] · 3: [] · 4: [(3,70)] — six pairs total, one per edge; row 3 is empty because no edge leaves vertex 3.

Must know: the (neighbour, weight) tuple form is the standard for algorithm code — Dijkstra's priority queue literally pushes (weight, vertex) pairs read from these lists; a matrix instead reads M[u][v] in one step but pays $\Theta(V^2)$ memory for the privilege. Pick by density: $E$ near $V^2$ → matrix; $E$ near $V$ → list.
