Prim's Algorithm

Prim's algorithm builds a minimum spanning tree (MST) of a connected, undirected, weighted graph: a subset of $V-1$ edges that connects all $V$ vertices with the smallest possible total weight. It grows one tree outward from a start vertex, and each round it commits the single cheapest edge that reaches a new vertex — a greedy choice justified by the cut property below.

The Cut Property

Split the vertices into two sets: the tree (visited) and everything else. The edges between them form a cut. The minimum-weight edge across any cut is always safe to add: some spanning tree must contain it, because exchanging it for any other crossing edge in that tree cannot increase the total weight. Prim's applies this with the cut tree vs. rest every round:

  1. Scan every edge leaving the tree (the cut edges).
  2. Select the one with minimum weight.
  3. Add it — the tree gains exactly one vertex, never a cycle.

What the animation shows: the demo graph on seven vertices 0–6 with undirected edges 0–1 (10), 0–2 (80), 1–2 (6), 1–4 (20), 2–3 (70), 4–5 (50), 4–6 (5), 5–6 (10), starting from vertex 0. Each round the cut edges flash one by one (the scan in the code), then the winner is announced ("Selected Edge: (0, 1), weight: 10") and the running "Minimum Cost" ticks up. Watch round two: the direct edge 0–2 (80) is a cut edge, but 1–2 (6) wins — reaching a vertex through the tree beats reaching it from the start.

Selected edges (verified against the reference implementation on this exact graph): (0, 1) w10 → (1, 2) w6 → (1, 4) w20 → (4, 6) w5 → (6, 5) w10 → (2, 3) w70, for a total MST cost of 121. The two heaviest edges, 0–2 (80) and 4–5 (50), are never used — the tree found cheaper routes around them.

Complexity

  • This scan-as-written: $O(V \cdot E)$ — the code does $V-1$ rounds, and each round rescans the full adjacency of every visited vertex, i.e. $O(E)$ work per round.
  • Standard array variant: $O(V^2)$ — instead of rescanning, keep a key[v] array ("cheapest edge reaching $v$ so far"). Each round scans $V$ keys for the minimum ($V$ rounds $\Rightarrow$ $V^2$ key comparisons) and each edge relaxes a key at most twice, adding $O(E)$.
  • Binary-heap variant: $O(E \log V)$ — the minimum search becomes a heap extract ($\log V$), and each of the $E$ edge relaxations updates the heap at $\log V$ cost. This is the version in the reference implementation; the animation shows the simpler scan because the flash of each cut edge is the algorithm's work.
  • Space: $O(V)$ beyond the graph itself — the visited set, the running total, and (in the array/heap variants) one key per vertex.

Best case = worst case here: the scan is unconditional, so $O(V \cdot E)$ as written and $O(V^2)$ for the array variant regardless of edge weights. With a Fibonacci heap the bound improves to $O(E + V \log V)$ — worth knowing, rarely worth implementing.

Must know: Prim's needs a connected graph to span everything (disconnected input leaves some vertices unreached); the cut property is the proof behind the greed; ties make the MST not necessarily unique, but the minimum total is; the graph must be undirected — for directed shortest paths see Dijkstra instead.

Applications

  • Network design: cheapest layout of cables, pipelines, or grid lines connecting all nodes.
  • Approximation: MSTs underpin the 2-approximation for the metric travelling salesperson problem.
  • Clustering: removing the largest MST edges splits data into natural groups.
  • Image segmentation: region growing treats pixels as a weighted graph — Prim's is literally a region grower.

Prim's vs. Kruskal's

Prim's Kruskal's
Grows one tree outward from a start vertex a forest that merges until it is one tree
Chooses cheapest edge leaving the tree globally cheapest edge that creates no cycle
Needs connected graph (to span all vertices) any graph — produces a spanning forest
Best for dense graphs ($O(V^2)$ array variant) sparse graphs ($O(E \log E)$ sort)

Both are greedy, both rely on the cut property, and both end with the same total weight. Continue with Kruskal's Algorithm to see the other strategy on the identical demo graph, or jump to Topological Sort for a different use of graph orderings.
