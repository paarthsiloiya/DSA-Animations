Dijkstra's Algorithm

Dijkstra's algorithm finds the shortest path from a start vertex to every other vertex in a graph with non-negative edge weights. It is greedy: it repeatedly commits to the unvisited vertex with the smallest tentative distance, safe in the knowledge that no shorter route to it can exist — an invariant that holds only while every edge weight is ≥ 0 (a negative edge could open a shorter route through an already-committed vertex, and the greedy choice would have been wrong).

The Greedy Invariant

Maintain for every vertex a tentative distance — the length of the best path found so far. Each round:

  1. Select the unvisited vertex with the minimum tentative distance.
  2. Commit it — its distance is now final (all other unvisited vertices are reachable only through distances at least as large, so no shorter path can appear later — this is exactly where non-negative weights are required).
  3. Relax its out-edges: a neighbour's tentative distance improves whenever dist[u] + weight < dist[v].

What the animation shows: the demo graph on seven vertices with directed edges 0→1 (10), 0→2 (80), 1→2 (6), 1→4 (20), 2→3 (70), 4→5 (50), 4→6 (5), 5→6 (10), start vertex 0. Distances start at ∞; vertex 0 is set to 0. Each round announces "Selecting the unvisited node with the minimum tentative distance", selects, then "Updating distances to the neighbouring nodes" with per-edge relaxations ("New Distance = 10 + 6"), and finally marks the vertex visited. Watch vertex 2: its direct edge gives 80, but the route through vertex 1 improves it to 16 — and vertex 6 ends at 35 via 0→1→4→6 rather than the direct-looking 0→2→… chain.

Final distances (verified against the reference implementation on this exact graph): 0: 0, 1: 10, 2: 16, 3: 86, 4: 30, 5: 80, 6: 35.

Complexity

  • This linear-scan variant: $O(V^2)$ — exactly what the animation and the code show: $V$ rounds, each scanning all $V$ vertices for the minimum (plus edge relaxations bounded by $E$; the scan dominates at $O(V^2)$).
  • With a binary heap: $O((V + E) \log V)$ — the standard optimization: a priority queue replaces the scan, each of the $V$ extractions and $E$ relaxations costing $O(\log V)$.
  • Space: $O(V)$ for the distance and visited arrays (plus the graph itself). Best case is still $O(V^2)$ for the linear variant — the scan is unconditional.

Must know: Dijkstra gives wrong answers with negative weights — use Bellman-Ford there. For all pairs at once, Floyd-Warshall solves every start vertex in one pass.
