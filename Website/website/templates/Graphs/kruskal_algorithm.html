Kruskal's Algorithm

Kruskal's algorithm builds a minimum spanning tree (MST) of a weighted graph by ignoring trees entirely at first: sort all edges by weight, then take them cheapest-first, skipping any edge whose two endpoints are already connected — because that edge would close a cycle and contribute nothing. The result is a forest of fragments that merges, edge by edge, into one minimum tree.

Sort, Take, Skip

The one insight doing all the work: if an edge's endpoints already lie in the same fragment, some cheaper path connects them, so the edge is redundant. Checking "same fragment?" is a union-find job — the code labels every vertex with its fragment and relabels one whole fragment on a merge (label propagation). The optimized version of that structure (union by rank with path compression) is what the reference implementation uses; it makes every check nearly $O(1)$ amortized.

Watch for the silent skips: edges whose endpoints already share a fragment — like (6, 4), the reverse copy of an accepted edge, and the heavy 0–2 (80) — produce no announcement at all; the scan simply moves on. That silence is the cycle check succeeding. After the sixth edge every vertex belongs to one fragment, so the remaining ten edge copies are all skipped.

Complexity

  • Best / Worst / Average: $O(E \log E)$ — the sort dominates. Each of the $E$ edges costs one union-find query; with union by rank + path compression that is $O(\alpha(V))$ amortized (inverse Ackermann, effectively constant), so the total is $O(E \log E) + O(E \,\alpha(V)) = O(E \log E)$ in every case — Kruskal's has no input order that skips the sort. Since $E \le V^2$, $\log E \le 2 \log V$, so this is commonly written $O(E \log V)$.
  • The label-propagation merge shown in the code: relabelling a fragment costs $O(V)$ per merge in the worst case, making this specific variant $O(E V)$ worst-case — honest about what the video shows. It is easy to follow visually and correct; rank-based union is the production upgrade.
  • Space: $O(V + E)$ — the sorted edge list plus one label per vertex.

Must know: Kruskal's never adds a cycle edge (the union-find check guarantees it); it can stop after $V-1$ accepts; it works on disconnected graphs, producing a minimum spanning forest — one tree per component; sorting is the whole time budget, so Kruskal's favours sparse graphs where $E \log E$ is small.

Applications

  • Network design: same MST use as Prim's — wiring, pipelines, road links at minimum cost.
  • Single-link clustering: cutting the largest MST edges clusters data by graph distance.
  • Circuit layout: minimum wire length between component pads.
  • Approximation algorithms: MST-based approximations (e.g. metric TSP) usually start from a Kruskal tree.
