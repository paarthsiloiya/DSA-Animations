Graph Traversals

A traversal visits every vertex reachable from a start vertex, exactly once. The two classic orders differ in one data structure: BFS (breadth-first search) processes a queue — the oldest discovery first — so it sweeps outward in levels; DFS (depth-first search) processes a stack — the newest discovery first — so it dives along one path before backtracking. The four animations below run both on the same 7-vertex demo graph, first undirected, then directed.

BFS — Undirected

The queue invariant: vertices enter the queue the moment they are discovered and leave in that same order — so BFS processes all vertices at distance $d$ before any vertex at distance $d+1$. That level property is exactly why BFS finds shortest paths in unweighted graphs: the first time it reaches a vertex, it has reached it via the fewest edges possible.

What the animation shows: the demo graph on vertices 1–7 with edges 1-2, 1-4, 2-4, 2-3, 2-5, 3-6, 5-6, 5-7, 6-7. Starting from node 1, each processed vertex reads "Processing node X" while the Queue display above tracks the container — watch it hold [1] → [2, 4] → [4, 3, 5] → … exactly the level frontier. The traversal edges are kept at the end as the BFS tree.

Visit order: 1 → 2 → 4 → 3 → 5 → 6 → 7 — levels 0: {1}, 1: {2, 4}, 2: {3, 5}, 3: {6, 7}, in that exact level order.

DFS — Undirected

Swap the queue for a stack and the character changes completely: the newest discovery is processed first, so DFS dives as deep as possible along one path and only backtracks when the path is exhausted. The video's Stack display shows that LIFO discipline directly.

What the animation shows: the same graph and start node 1, but the container is a Stack — the label literally reads "Stack: [...]". Note the neighbour order is reversed on purpose (the code's reversed(...) line): the stack then pops the lowest-numbered neighbour first, so the dive follows the natural 1–2–3–6–7 chain rather than jumping. The kept edges form the DFS tree.

Visit order: 1 → 2 → 3 → 6 → 7 → 5 → 4 — one long dive 1-2-3-6-7, backtrack to 6, take 5, backtrack twice, finally 4. Compare with BFS's level order on the same graph.

BFS — Directed

Nothing about the algorithm changes on a digraph — only the edges are one-way now. Neighbours come from the out-adjacency only, so a vertex is reachable only along the arrows. The demo uses the same nine edges, now oriented exactly as the scene draws them.

What the animation shows: the same seven vertices but each edge carries an arrow; the adjacency in the code lists only out-edges (2: [4, 3, 5] — no back-entry 1). The queue mechanics are identical to the undirected video; the directed edges each light up with their orientation.

Visit order: 1 → 2 → 4 → 3 → 5 → 6 → 7 — the same order as the undirected BFS here, because every undirected edge happened to be traversed in its recorded direction. Change one arrow (e.g. 2→1 becomes 1→2 only) and the reachable set itself would change — that is the directed caveat.

DFS — Directed

DFS on a digraph is the backbone of cycle detection, topological sort (the finish order is a valid topological order reversed), and strongly connected components. Its stack behaviour is identical to the undirected case; what changes is that the traversal follows arrows only — a vertex reachable only against an arrow is never discovered from this start.

What the animation shows: arrows only, Stack display, reversed neighbour order. The dive 1 → 2 → 3 → 6 → 7 exhausts its arrows, backtracks, picks up 5 (whose out-edges 5→6, 5→7 are already discovered), backtracks again, and finishes with 4 — every edge in this demo points "downhill", so no back-edge is ever traversed; the kept DFS-tree edges are all one-way, exactly the kind of orientation a topological sort consumes.

Visit order: 1 → 2 → 3 → 6 → 7 → 5 → 4 — identical to the undirected DFS order for the same reason as BFS above: the demo's edge orientations happen to align with the undirected traversal. The structure is what differs: the kept DFS-tree edges are all one-way here.

Must know: both algorithms visit each vertex once and each edge at most twice (once per endpoint in the undirected case), giving $O(V + E)$ time and $O(V)$ space (visited set + container) — matching the reference implementations. BFS's shortest-path property holds only in unweighted graphs (in weighted graphs use Dijkstra); DFS's order is not "shortest" anything, but its finish order powers topological sort and SCC algorithms.

Applications: BFS — shortest paths (unweighted), level/degree analysis, web crawlers, social-network "degrees of separation". DFS — cycle detection, topological sort, SCCs, maze/path existence.
