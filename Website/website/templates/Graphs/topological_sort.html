Topological Sort

A topological sort of a directed acyclic graph (DAG) is a linear order of its vertices in which every edge points forward: for each edge $u \to v$, vertex $u$ appears before $v$. Think of course prerequisites, build dependencies, or task pipelines: the sort is any schedule that violates no dependency. Cycles make this impossible — a dependency loop has no valid order, which is exactly why the algorithm only applies to DAGs.

Kahn's Algorithm (indegree counting)

The animation shows the classic queue-based method. Each vertex carries an indegree — the number of edges arriving at it, the number of unfinished prerequisites. A vertex with indegree zero has none: it can go now. Taking it doesn't just append it to the order — removing it frees its outgoing edges, decrementing each neighbour's indegree, possibly pushing a neighbour down to zero and into the queue:

  1. Count every vertex's indegree; enqueue all that start at zero.
  2. Pop a vertex, append it to the order, and decrement each neighbour's indegree.
  3. Any neighbour that reaches zero joins the queue. Repeat until it empties.

What the animation shows: an 8-vertex DAG with edges 0→2, 0→3, 0→4, 1→2, 1→7, 2→5, 3→5, 3→7, 4→7, 5→6, 6→7. The indegree of each vertex fades in as a number (vertex 1 gets the explicit "←Indegree" callout). Vertices 0 and 1 start at zero, so both are available immediately; each round announces the "Selected Vertex", its freed edges fade out, and the vertex physically moves onto the ordering line at the bottom.

The order produced (validated edge-by-edge on this exact graph): 0, 1, 3, 4, 2, 5, 6, 7 — check any edge against it, the earlier vertex always comes first. All 8 vertices appear, which certifies the graph has no cycle. Note the queue chose 3 before 2: when a zero-indegree vertex is available the FIFO queue takes the oldest one, but any zero-indegree vertex is a legal choice — topological orders are never unique.

Complexity

  • Best / Worst / Average: $O(V + E)$ — counting indegrees touches each edge once ($E$); each vertex enters and leaves the queue at most once ($V$); each freed edge is decremented exactly once ($E$). Nothing depends on the shape of the graph, so every case is linear in the graph's size.
  • Space: $O(V)$ beyond the graph itself — one indegree counter, one queue slot, and one output position per vertex (the queue never holds more than $V$ entries).

Must know: the output length is a cycle detector — fewer than $V$ vertices at the end means every leftover vertex sits on a cycle (this is a standard way to detect cycles in a directed graph); the order is not unique, and which one you get depends on the queue's tie-breaking; the input must be a DAG; the DFS alternative (reverse post-order finish times) produces the same guarantees with the same $O(V + E)$.

Applications

  • Build systems: compile/link order derived from file dependency graphs.
  • Course scheduling: prerequisites define the DAG; the sort is any legal study plan.
  • Task pipelines: spreadsheet recalculation, dataflow execution, PERT/CPM project scheduling.
  • Instruction scheduling: CPUs order independent instructions within dependency limits.

Kahn's vs. DFS Topological Sort

Kahn's (queue) DFS (finish times)
Idea peel off zero-indegree vertices reverse the finish order of a DFS
Cycle detection free — short output means cycle needs an explicit back-edge check
Streaming yes — outputs vertices as they free up no — order known only after the full DFS
Time $O(V + E)$ $O(V + E)$

Both orders are valid topological sorts of the same DAG — possibly different ones. Revisit the ingredients in Graph Traversals (BFS runs Kahn's skeleton; DFS powers the alternative), or continue the weighted-graph tour with Prim's and Kruskal's.
