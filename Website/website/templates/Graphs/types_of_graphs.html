Types of Graphs

A graph is a set of vertices (nodes) connected by edges — the standard model for networks: roads, social connections, computer links, task dependencies. Before running any algorithm on one, you need its vocabulary: are the edges two-way or one-way? Do they carry costs? How many edges touch a node? The four animations below introduce exactly those distinctions, each on a 5-vertex demo graph.

Undirected Graphs

In an undirected graph every edge runs both ways: the edge (0, 2) links vertex 0 and vertex 2 with no direction — you can walk from either end to the other. Each vertex has a degree: the number of edges touching it.

What the animation shows: the five vertices 0–4 fade in, one is labelled Node, then the seven edges appear one at a time — 0–2, 0–1, 1–3, 4–1, 4–2, 2–3, 3–4 — with the first one labelled Edge. Finally the degrees appear under every vertex: 0: 2, 1: 3, 2: 3, 3: 3, 4: 3 — check any one, e.g. vertex 0 touches exactly the edges 0–2 and 0–1, so its degree is 2. The handshake lemma follows from this counting: summing all degrees counts every edge twice, so the total is always $2|E|$ (here $2 \times 7 = 14$, and indeed $2+3+3+3+3 = 14$).

Directed Graphs

A directed graph (digraph) gives every edge an orientation: (0, 2) means from 0 to 2 only — drawn with an arrow. Each vertex now has two counts: the in-degree (edges arriving at it) and the out-degree (edges leaving it).

What the animation shows: the same five vertices and seven edges as the undirected video — but now each edge text reads 0->2, 0->1, 1->3, 4->1, 4->2, 2->3, 3->4 with arrows. The in-degrees fade in first (0: 0, 1: 2, 2: 2, 3: 2, 4: 1), then the out-degrees (0: 2, 1: 1, 2: 1, 3: 1, 4: 2). Vertex 0 has in-degree 0 (nothing arrives) and out-degree 2 — a source. The directed version of the handshake lemma: total in-degree = total out-degree = $|E|$ (both sum to 7 here).

Weighted Undirected Graphs

A weighted graph attaches a cost to every edge — distance, time, price, capacity. In the undirected case the weight belongs to the pair: travelling 0–3 costs the same in either direction.

What the animation shows: five vertices, then six weighted edges drawn one at a time — 0–1 (10), 0–3 (18), 1–2 (20), 1–3 (6), 2–4 (8), 3–4 (70) — each labelled u–v with its weight displayed on the edge, the last one circled as Weight. These are exactly the demo weights the shortest-path and MST algorithms on the later pages operate on.

Weighted Directed Graphs

The fully general form: every edge has an arrow and a cost — the model behind road networks with one-way streets, routing tables, and dependency graphs with durations.

What the animation shows: the same six weights as the undirected version — 0->1 (10), 0->3 (18), 1->2 (20), 1->3 (6), 2->4 (8), 3->4 (70) — but each edge is now an arrow, so 3–4 costs 70 from 3 to 4 and cannot be walked backwards. Dijkstra's and Bellman-Ford's animations on the later pages build on exactly this shape.

Must know: direction and weight are independent choices — any of the four combinations is a legitimate graph type, and the algorithms you can run depend on both (e.g. plain BFS/DFS ignore weights; shortest-path algorithms need them; topological sort needs direction).
