Interval Scheduling

Interval scheduling asks for the largest possible set of non-overlapping intervals — the most meetings one room can host, the most jobs one machine can run. It is the canonical greedy problem: one sorted pass, one rule, provably optimal. The rule: always take the interval that finishes earliest.

Why Earliest Finish Wins (the Exchange Argument)

Intuitively: an interval that ends early blocks the least amount of the future. Formally, suppose some optimal schedule OPT does not start with the earliest-finishing interval $g$ that the greedy choice takes. Let $x$ be the interval of OPT that ends first. Since $g$ has the minimum finish time, $g$ ends no later than $x$ — so swapping $x$ out for $g$ breaks nothing after it ($g$'s successors in OPT start when $x$ ended, and $g$ is gone by then). The swap keeps the schedule the same size, and now it contains the greedy choice. Repeat the argument on the remaining intervals: the greedy schedule is never behind OPT — so it is optimal. This "greedy stays ahead" / exchange pattern is the template for proving greedy algorithms correct.

What the animation shows: nine demo intervals (id, start, finish): 0:[1,2], 1:[3,6], 2:[1,5], 3:[4,7], 4:[2,5], 5:[5,8], 6:[7,10], 7:[10,13], 8:[9,12] laid on a time ruler. The rows re-order into finish-time order, then the scan begins: the first interval is always accepted; each subsequent one is announced ("Processing interval i") and either fits — "No overlap with last accepted" — or collides — "Overlaps with last accepted" with the last one flashing as the witness. The rejected intervals fade away and the winners line up on a single track.

Verified result: the greedy selects ids 0, 4, 5, 8 — [1,2], [2,5], [5,8], [9,12] — four intervals. An exhaustive check of all $2^9$ subsets confirms 4 is the maximum possible (note the touching rule: interval 4 starts exactly at interval 0's finish, s ≥ f counts as compatible — the scene's rule). Other optimal sets of size 4 exist (e.g. 0, 1, 6, 7); the greedy one is among them, guaranteed.

Complexity

  • Best / Worst / Average: $O(n \log n)$ — the sort by finish time costs $O(n \log n)$ and dominates the scan, which is strictly $O(n)$: each interval is compared against the running last_finish exactly once. No input escapes the sort, so every case carries the same bound. With intervals pre-sorted, the scan alone is $O(n)$.
  • Space: $O(n)$ for the sorted order (or $O(1)$ extra if sorting in place), plus $O(n)$ to report the accepted set.

Must know: sorting by finish is the only rule that works — sorting by start fails (a long early interval blocks everything), and sorting by duration fails too (a short middle interval can sit across two neighbours); the proof is the exchange argument above; if intervals carry weights, greedy fails and the problem needs dynamic programming (weighted interval scheduling); with $k$ rooms instead of one, the greedy switches to earliest start plus a min-heap of room release times (interval partitioning).

Applications

  • Meeting-room booking: maximizing the meetings one room can host.
  • Job scheduling: single-machine tasks with fixed start/end windows.
  • Bandwidth allocation: packing non-overlapping transmission requests.
  • Event timetabling: maximizing attendance across fixed sessions.

Which Greedy Rule Works?

Sort by Optimal? Why
Earliest finish yes leaves the most room after it (exchange argument)
Earliest start no a long interval can start first and block everything
Shortest duration no a short interval can straddle two compatible ones
