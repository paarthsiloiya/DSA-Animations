Longest Common Subsequence

A subsequence keeps the order of a sequence but may skip items; the Longest Common Subsequence (LCS) of two strings is the longest subsequence appearing in both. Comparing two files, two DNA strands, or two versions of anything comes down to this problem — and it is solved with dynamic programming: a table whose cells only depend on their neighbours, filled once and read back for the answer.

A note on placement: the LCS is a dynamic-programming algorithm, not divide & conquer — it lives in this section because it rounds out the classic divide-and-conquer comparisons covered here (and its linear-space variant, Hirschberg's algorithm, actually is divide & conquer).

The Table and the Traceback

The animation fills an $(m{+}1) \times (n{+}1)$ table of suffix LCS lengths — lcs[i][j] = length of the LCS of u[i:] and v[j:]:

  • Match: if u[i] == v[j], that character extends the best suffix pair: lcs[i][j] = lcs[i+1][j+1] + 1.
  • Mismatch: otherwise drop one character from either side and keep the better: lcs[i][j] = max(lcs[i+1][j], lcs[i][j+1]).

The video fills this table backwards — from the bottom-right corner toward the top-left, so the final answer lands in lcs[0][0]; the forward orientation (prefixes, answer bottom-right) is the same algorithm with the axes flipped. Once the table is full, a walk from the corner back through the arrows recovers the string itself.

What the animation shows: the demo strings u = "bisect" and v = "secret" — chosen equal length purely so the table lays out square on screen; the algorithm itself works on any pair of lengths. Every cell announces itself ("Processing cell"), compares the row and column characters ('s' == 's' ✓ / 'b' != 's' ✗) and writes its value via the diagonal or max rule. The drawn path then traces the traceback, the matched characters light up in both header rows, and the result appears: LCS "sect" (Length 4).

Verified: the backward table and traceback shown in the video and an independent forward-prefixes DP both give length 4 with the string "sect" — s e c t appear in order inside both bisect and secret.

Complexity

  • Best / Worst / Average: $\Theta(mn)$ — the table has $(m{+}1)(n{+}1)$ cells and each one costs $O(1)$ (one comparison plus one or two table reads). Nothing about the input skips cells: matches and mismatches alike fill the whole table, so every case is quadratic in the product.
  • Space: $\Theta(mn)$ for the full table — needed here because the traceback reads it. If only the length is wanted, a rolling pair of rows suffices: $\Theta(\min(m, n))$. Recovering the string with that little memory is still possible — Hirschberg's divide & conquer refinement recomputes halves around the split row in $\Theta(mn)$ time and $\Theta(\min(m, n))$ space.

Must know: a subsequence is not a substring — it need not be contiguous ("sect" skips letters in both demo strings); the LCS is not necessarily unique (ties in the max rule lead to different valid strings); lcs length relates to edit distance under insert/delete-only editing: $\text{dist} = m + n - 2 \cdot \text{LCS}$; and the two fill directions (prefixes vs suffixes) are mirror images, so don't let the video's backward fill suggest a different algorithm.

Applications

  • File diffing: diff-style tools align two versions via their LCS.
  • Bioinformatics: DNA/protein sequence similarity; with weighted matches it becomes global alignment (Needleman–Wunsch).
  • Version control & sync: merging changes by longest common ancestry of text.
  • Plagiarism / similarity detection: longest shared passage of token sequences.
