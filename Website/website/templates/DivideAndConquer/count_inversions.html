Count Inversions

An inversion in an array is a pair of positions out of order: indices $i < j$ where $a[i] > a[j]$. A sorted array has none; a reversed array has all $\binom{n}{2}$ of them — so the inversion count measures how far an array is from sorted. Counting by checking every pair is $O(n^2)$; the divide & conquer trick below counts them in $O(n \log n)$, almost as a side effect of merge sort.

Merge Sort That Counts

Split the array in half and count each half's inversions recursively. The only uncounted inversions left are split inversions — pairs with one element in each half. Sorting both halves reveals them for free during the merge: whenever the merge takes a right element while left elements remain, that right element is smaller than every remaining left element — each one an inversion, counted in a single line.

What the animation shows: two scrambled rows of the letters A–F. The top row fixes the mapping (E=1, B=2, D=3, F=4, C=5, A=6), and the bottom row F B E A D C converts to the number array [4, 2, 1, 6, 3, 5]. A recursive merge sort then plays out with a running "Inversions" counter: subarrays get framed, halves get compared element by element, and every time a right element beats the current left element the counter jumps by however many left elements remain ("2 > 1 (+1 inversions)").

Verified count: the demo array has exactly 6 inversions — the merge-sort counter and an independent $O(n^2)$ brute-force check agree on the six pairs (4, 2), (4, 1), (4, 3), (2, 1), (6, 3), (6, 5) — and the sort ends with the array fully ordered as [1, 2, 3, 4, 5, 6].

Complexity

  • Best / Worst / Average: $\Theta(n \log n)$ — the same recurrence as merge sort: $T(n) = 2T(n/2) + \Theta(n)$. The recursion tree has $\log_2 n$ levels and every level does $\Theta(n)$ merge work (each element is compared and moved a constant number of times per level), so $\Theta(n) \cdot \log_2 n = \Theta(n \log n)$ — equivalently, the master theorem with $a = 2$, $b = 2$, $f(n) = \Theta(n) = \Theta(n^{\log_b a})$ (case 2). The counting itself is $O(1)$ inside the merge, so it changes nothing. No case is better or worse: the merge happens unconditionally.
  • Space: $\Theta(n)$ for the merged temporary copy, plus $\Theta(\log n)$ recursion stack. Same profile as merge sort itself.

Must know: the stable comparison (≤, not <) keeps equal elements from being miscounted; the maximum inversion count is $n(n-1)/2$ (fully reversed); an array with $k$ inversions is exactly $k$ adjacent swaps away from sorted; the same merge-counting skeleton gives the standard $O(n \log n)$ algorithm behind the Kendall tau rank correlation.

Applications

  • Ranking similarity: Kendall's tau between two rankings is built from their inversion count.
  • Recommendation systems: measuring how much one user's ordering disagrees with another's.
  • Estimating sort effort: how far a nearly-sorted input is from ordered.
  • Genomics: counting reversed gene segments between chromosomes.

Brute Force vs. Merge-Counting

Check all pairs Merge sort + count
Time $\Theta(n^2)$ $\Theta(n \log n)$
Extra space $O(1)$ $\Theta(n)$
Also gives you the pair list (if you store it) a sorted array for free
